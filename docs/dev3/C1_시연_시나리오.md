## 🎯 시나리오 1 — RANSOMWARE (랜섬웨어)

**스토리**: 새벽 02:00 비상 알림. NCP Object Storage 의 240GB 객체가 갑자기 .locked 확장자로 변경됨. CISO 가 V-1 Setup 으로 사고 접수 시작.

### Step 0 — CSP
- 선택: **Naver Cloud (NCP)**

### Step 1 — 케이스 메타
- 제목: `랜섬웨어 의심 — Object Storage 대량 암호화`
- 발생 시각: `2026-05-19 02:00`
- Severity: **Critical**
- TLP: **RED** (내부만, 다크웹 협박 가능성)

### Step 2 — Discovery Loop

#### ① 단서 입력 (CluesInput)
| 단서 유형 | 값 |
|---|---|
| `HASH:known_malicious` | `ransom_note.txt SHA-256 7a8b9c...` |
| `TIME_WINDOW:off_hours` | `2026-05-19 02:00 ~ 03:30` |
| `SERVICE:object_storage` | NCP Object Storage |
| `IP_ADDRESS:tor_vpn` | `203.0.113.50` (탐지 도구 매칭) |

#### ② 부분 로그 분석 (PartialLogAnalysis)
- 업로드: `backend/data/synthetic/ncp_none.json` (또는 사용자 보유 raw)
- 매칭 기법: **T1486 (Data Encrypted for Impact)**, **T1490 (Inhibit System Recovery)**

#### ③ 결정 트리 진행
- **Q1**: `service_anomaly` (서비스 이상) 선택
- **Q2D**: `mass_encryption` (대량 객체 암호화 발견) 선택 ← 🆕 신규 옵션
- **Q3**: `weekend_dawn` (주말 새벽) 선택 (있다면)

#### 예상 누적 점수 (RANSOMWARE)

→ Triage outcome: **`auto_confirm`** (RANSOMWARE 자동 확정)

## 🎯 시나리오 2 — MISCONFIG_EXPOSURE (설정 오류 노출)

**스토리**: 외부 보안 연구자가 이메일로 "귀사 NCP Object Storage 의 customers-data 컨테이너가 public-read 입니다" 신고. 14일간 노출 추정.

- 선택: **NCP**

### Step 1 — 케이스 메타
- 제목: `Object Storage public 노출 — 외부 연구자 신고`
- 발생 시각: `2026-04-01 09:00` (정책 변경 시각, 추정)
- Severity: **High**
- TLP: **AMBER**

| 단서 유형 | 값 |
|---|---|
| `SERVICE:object_storage` | NCP Object Storage |

| `IP_ADDRESS:non_korean` | 외부 다운로드 IP 다수 |

- **Q3**: `policy_changed` (정책 변경 흔적) — 있다면

## 🎯 시나리오 3 — PHISH_INITIAL_ACCESS (피싱 초기 침투)

- 발생 시각: `2026-02-10 08:42` (공격자 IP 첫 로그인)

- TLP: **AMBER**

## ⚠️ 주의 사항

1. **사용자가 단서 입력 시 weight_key 매칭이 정확해야 점수 누적됨**. UI 의 ClueType selector 값이 weights.json 의 `IP_ADDRESS:non_korean` 같은 키와 1:1 일치해야 함.
2. **신규 4종 모두 합성 raw 로그는 미작성** (작업 지시서 §3 범위 밖). 실 검증은 부분 로그 분석을 텍스트 입력으로 갈음.
3. **임계값 도달 시 자동 진행** — `auto_skip(90)` 도달 시 추가 질문 없이 Step 3 진행 가능. UI 토글로 강제 진행/추가 단서 둘 다 가능.
4. **9종 + UNCLASSIFIED = 10 enum** — 모든 응답 객체에 10 키가 일관되게 들어와야 함.
