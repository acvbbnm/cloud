## 0. 배경

### 현재 결정 트리의 약점 (사용자 시연 후 발견, 2026-05-21)

```
현행: Q1 인지 경로 → Q2 직접 정황 → Q3 추가 패턴 → T_evaluate  (3 단계)
```

**문제**:
- 너무 짧고 단순 — 3 답변만으로 사고유형 확정 시도
- "꼬리에 꼬리를 무는" 사용자 요구 와 불일치
- 의료 감별진단(Differential Diagnosis) 처럼 가설 좁히기·의외성 노출 부재
- 각 답변이 사고유형 변별의 결정적 시그널을 묻지 않음
- 점수 단순 누적 → 사용자가 "왜 이 가설인지" 추적 어려움

### 사용자 요구

> "꼬리에 꼬리를 무는 진단. 답변마다 가설이 좁혀지고 의외성이 노출되며 신뢰도가 시각화되어야"

→ 본 문서의 핵심 비전.

### 학술 변호 강화 의도

- NIST SP 800-61r2 §3.2 Triage 의 6단계 indicator-driven 진단 흐름 정확 구현
- 의료 감별진단 (Differential Diagnosis) 의 점진적 가설 좁히기 결합
- AWS Detective Profile-by-Profile pivot 패턴 차용
- 결정성 100% + 신뢰도 게이지 + 동적 분기

## 1. 비전 + 핵심 원칙

### 비전 한 줄

> **Investigative Diagnostic Tree** — 6단계 동적 분기 결정 트리 + 실시간 진단 UX

### 핵심 원칙 5

1. **결정성 100%** — 모든 가중치·분기 룰 정적 JSON. 같은 입력 → 같은 출력.
2. **동적 분기** — 각 노드의 next 가 이전 답변 조합으로 결정 (의료 감별진단)
3. **실시간 가시성** — 답변 → 점수 변화 애니메이션 + 신뢰도 게이지 + 격차 hint
4. **AI 판단 X** — 점수·분기 룰만 사용. AI 는 KB 검색만 (V-8 셰르파)
5. **사용자 의도 우선** — 명시 답변 우선, 자동 분류는 fallback

## 2. 6단계 트리 구조

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                              │
│  Q1 사고 인지 경로 (5 옵션, 공통) ── 기존                                  │
│   │  ⦿ csp_alert  ⦿ external_report  ⦿ audit  ⦿ service_anomaly  ⦿ unknown │
│   │                                                                          │
│   ▼                                                                          │
│  Q2 직접 정황 (Q1 별 5종 분기, 각 5-7 옵션, 다중 선택) ── 기존            │
│   │                                                                          │
│   ▼                                                                          │
│  Q3 추가 패턴 (Q2 답변 조합별 동적 분기, 4-5 옵션) ── 기존                │
│   │                                                                          │
│   ▼                                                                          │
│  Q4 ★ 증거 무결성 + 시간축 (Q3 별 분기, 3-4 옵션) ── 신규                │
│   • 감사 로그 비활성·삭제 흔적                                              │
│   • 사고 시작 추정 시점 (수시간/수일/수주/미상)                            │
│   • 백업·스냅샷 무결성 (확인됨/손상/미상)                                  │
│   • MFA 우회 흔적 (CRED 변별)                                              │
│   │                                                                          │
│   ▼                                                                          │
│  Q5 ★ 영향 범위 + 행위자 (Q4 별 분기, 3-4 옵션) ── 신규                  │
│   • 영향받은 자원 수 (단일/소수/광범위)                                    │
│   • 행위자 추정 (외부 IP / 내부 계정 / 협력사 / 미상)                       │
│   • 데이터 민감도 (개인정보 / 영업비밀 / 일반)                              │
│   │                                                                          │
│   ▼                                                                          │
│  Q6 ★ 후속 시그널 + 의도 (Q5 별 분기, 3-4 옵션) ── 신규                  │
│   • 랜섬 노트·협박 메시지 (RANSOM 확정)                                    │
│   • 데이터 변조·파괴 흔적 (RANSOM/DATA 변별)                              │
│   • 계정 잠금·서비스 중단                                                  │
│   • 추가 횡적 이동 시그널                                                  │
│   │                                                                          │
│   ▼                                                                          │
│  T_evaluate (종합 + 신뢰도 게이지 + 사고유형 비교 차트)                    │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 노드별 책임

| 노드 | 역할 | 학술 정합 |
|---|---|---|
| Q1 | 사고 인지 경로 식별 | NIST 800-61r2 §3.2 표 3-2 indicator sources |
| Q2 | 직접 정황 — 1차 분류 | KISA 2025-08 제2장 초기 대응 점검표 6항목 |
| Q3 | 추가 패턴 — 시그널 정렬 | KISA 제3장 사고유형별 대응 1차 분류 |
| **Q4** | **증거 무결성·시간축** | NIST SP 800-86 §3 Volatility Hierarchy + 의료 "현재 상태" |
| **Q5** | **영향 범위·행위자** | ISO/IEC 27035-1:2023 Assess & Decide (impact assessment) + 의료 "전파 범위" |
| **Q6** | **후속 시그널·의도** | AWS Detective Profile-by-Profile pivot + 의료 "사후 변화" |
| T_evaluate | 종합 판정 + 신뢰도 시각화 | NIST 800-61r2 §3.2.4 incident analysis 종합 |

## 3. 동적 분기 룰 (Q3 → Q4 → Q5 → Q6)

### 분기 키 매핑

각 노드의 next 는 **이전 답변 조합** 으로 결정. weights·decision_tree JSON 에 룰 정의.

### 흐름 A — 자격증명 탈취 변별

```
Q1 csp_alert
  → Q2A "비정상 로그인"
    → Q3-CRED "실패→성공 인증 패턴"
      → Q4-CRED "MFA 우회 흔적?"
         ⦿ MFA 토큰 재사용 (PHISH/0ktapus 시그널)        +PHISH 25
         ⦿ MFA 등록 변경 (사용자 직접 우회)              +CRED 20
         ⦿ MFA 미적용                                    +CRED 15
        → Q5-CRED "행위자 추정?"
           ⦿ 비국내 IP (외부)                            +CRED 25
           ⦿ 내부 사내 IP                                +INSIDER 20
           ⦿ Tor·VPN exit                                +CRED 30
          → Q6-CRED "후속 시그널?"
             ⦿ 즉시 권한 변경 → CRED + PRIV 복합        +PRIV 25
             ⦿ Object Storage 다운로드 → CRED→DATA      +DATA 20
             ⦿ Cloud Function 신규 → PERSIST            +PRIV 15
             ⦿ 후속 시그널 없음 → CRED 단독              +CRED 10
```

### 흐름 B — 랜섬웨어 변별

```
Q1 service_anomaly
  → Q2D "데이터 변조·파괴"
    → Q3-IMPACT "정책 변경 동반?"
      → Q4-RANSOM "백업 무결성?"
         ⦿ 백업 삭제·암호화 (T1490)                     +RANSOM 30
         ⦿ 백업 정상                                    +DATA 15
         ⦿ 백업 없음                                    +RANSOM 15
        → Q5-RANSOM "영향 범위?"
           ⦿ 단일 인스턴스                              +RANSOM 10
           ⦿ Object Storage 전체                        +RANSOM 25
           ⦿ 멀티 리전·계정                              +RANSOM 35
          → Q6-RANSOM "랜섬 노트?"
             ⦿ 노트 발견 (확정 RANSOM)                   +RANSOM 35
             ⦿ 데이터 유출 동반 (Double Extortion)       +RANSOM 30, +DATA 20
             ⦿ 노트 없음 (T1485 단순 파괴)               +RANSOM 15
```

### 흐름 C — MISCONFIG 변별

```
Q1 external_report
  → Q2B "데이터 외부 노출 확인"
    → Q3-DATA "Object Storage 정책 변경?"
      → Q4-MISCFG "공개 변경 시점?"
         ⦿ 외부 신고 직전 (의도적)                      +MISCFG 20
         ⦿ 사고 발견 이전 장기 노출 (실수)              +MISCFG 35
         ⦿ 미상                                          +MISCFG 10
        → Q5-MISCFG "변경 주체?"
           ⦿ 운영자 권한 (실수)                          +MISCFG 25
           ⦿ 비정상 IP (침해)                            +CRED 20, +MISCFG 5
           ⦿ 자동화 스크립트                              +MISCFG 15
          → Q6-MISCFG "데이터 민감도?"
             ⦿ 개인정보 (GDPR·개보법)                     +DATA 25
             ⦿ 영업비밀                                  +DATA 20
             ⦿ 일반 공개 데이터                          +MISCFG 5
```

### 흐름 D — INSIDER 변별

```
Q1 audit
  → Q2C "권한 변경 이력 다수"
    → Q3-INSIDER "비표준 시각 작업?"
      → Q4-INSIDER "사용자 직무 범위?"
         ⦿ 직무 범위 초과                                +INSIDER 30
         ⦿ 직무 범위 내 (정상)                          +INSIDER -5 (감점)
         ⦿ 협력사 계정                                  +INSIDER 25
        → Q5-INSIDER "행위자 가시성?"
           ⦿ 사내 단말                                  +INSIDER 25
           ⦿ 사내 IP + 외부 VPN                          +INSIDER 30
           ⦿ 자기 흔적 삭제 (s3credential.delete)        +INSIDER 35, +AUDIT 15
          → Q6-INSIDER "사후 행동?"
             ⦿ 정상 종료                                +INSIDER 10
             ⦿ 데이터 외부 전송                          +DATA 20
             ⦿ 자기 IAM 삭제                            +AUDIT 20
```

### 흐름 E — UNCLASSIFIED 회피 흐름 (Q1=unknown)

```
Q1 unknown → 즉시 Q4-MIN 으로 점프 (Q2·Q3 건너뜀)
  Q4-MIN: "현재까지 알고 있는 정황은?" (자유 답변)
  → Q5·Q6 으로 진행 또는 [UNCLASSIFIED 진행] 즉시 확정
```

## 4. UX 강화 8개 항목

### 4-1. 실시간 가설 점수 애니메이션 (FX)
- 매 답변 직후 우측 패널 막대 부드러운 증가 (300ms transition)
- 사고유형별 색상 + 가장 큰 증가 항목 강조 (sparkle 효과)
- 점수 변화량 `+N` 토스트 (3초)

**구현 위치**: `frontend/src/views/V1_Setup/Step2_Discovery.tsx` 의 우측 패널
**기술**: Framer Motion 또는 CSS transition + zustand subscribe

### 4-2. 답변별 영향 미리보기 (Hover Preview)
- 각 답변 버튼 hover 시 tooltip:
  ```
  이 답변 선택 시:
  CRED  ████████░░ +25
  PHISH ███░░░░░░░ +15
  → 예상 1위: CREDENTIAL_THEFT (45점)
  ```
- 결정성 100% 학술 변호력 ↑ (사용자가 알고리즘 투명하게 봄)

**구현**: `weights.json` 의 답변별 dict 를 미리 로드 → React Tooltip

### 4-3. 사고유형 신뢰도 게이지
- 1위 사고유형의 신뢰도 = `score / threshold_high_confidence(70)` 비율
- 비주얼: **원형 게이지 (0-100%)** 또는 진행률 막대
- 색상 단계:
  - 0-40%: 회색 — "단서 부족"
  - 40-70%: 파랑 — "가설 형성 중"
  - 70-90%: 초록 — "🎯 가설 형성"
  - 90%+: 강조 + 펄스 — "✅ 자동 확정 가능"
- 격차 < 20 시 amber 색 + "⚠ 복합 사고 의심"

**구현 위치**: 우측 패널 상단 + T_evaluate 화면

### 4-4. 격차 기반 진단 hint
- 매 답변 후 1위·2위 점수 격차 계산
- 토스트 동적:
  | 격차 | 토스트 |
  |---|---|
  | gap < 10 | `⚠ 여전히 모호 — 추가 질문 권장` |
  | gap 10-20 | `가설 형성 중 — Q4·Q5 진행` |
  | gap 20-30 | `🎯 명확해지는 중` |
  | gap ≥ 30 | `🎯 명확 — 조기 확정 가능` + **"바로 확정" 인라인 버튼** |

**구현**: `Step2_Discovery.tsx` 의 handleSubmitAnswer 응답 후

### 4-5. 답변 timeline (Stepper)
- Step 2 상단에 진행한 Q1~Q6 답변 요약 stepper
- 각 단계 클릭 시 해당 노드 답변 수정 (점수 자동 재계산 + Q4~Q6 재진행)
- 시각화:
  ```
  Q1✓ csp_alert → Q2A✓ 비정상로그인 → Q3✓ 실패→성공 → ▷ Q4 진행 중
  ```

**구현**: 신규 컴포넌트 `frontend/src/components/TriageStepper.tsx`

### 4-6. 조기 종료 인라인 카드
- 점수 90+ 도달 시 트리 진행 중에도 자동 노출:
  ```
  🎯 CREDENTIAL_THEFT 신뢰도 95% — 더 질문하시겠습니까?
  [지금 확정]  [Q4·Q5·Q6 계속 진행]
  ```
- 사용자가 "계속 진행" 선택 시 추가 가설(복합 사고) 발견 가능성 ↑

**구현**: `Step2_Discovery.tsx` 의 recommendation outcome=auto_skip 시

### 4-7. 트리 시각화 미니맵 강화
- 기존 `TriageTreeMinimap.tsx` 확장:
  - 사고유형별 색상 (CRED=blue, RANSOM=red, MISCFG=orange, PHISH=purple, INSIDER=teal, ...)
  - 분기 시각화 — Q3→Q4 가 사고유형별 다른 경로
  - **답변에 따라 갈 수 있는 다른 경로** 도 회색 점선으로 표시
  - 학술 변호: "다른 선택이 가능했음" 시각적 입증

### 4-8. 사고유형 비교 차트
- T_evaluate (또는 진행 중 클릭) 시 펼침
- 8 사고유형 막대 그래프 + 각 사고유형의 누적 가중치 출처 breakdown:
  ```
  CRED 165점
    ├─ environment_modifiers: +55
    ├─ 단서 (3개): +30
    ├─ 부분 로그: +15
    └─ 결정 트리 (Q1~Q6): +65
  ```
- 학술 변호: 점수 출처 100% 투명, 재현 가능

**구현**: 신규 컴포넌트 `frontend/src/components/HypothesisBreakdownChart.tsx`

## 5. 가중치 매트릭스 확장 규모

### 신규 키 ~56 개

| 영역 | 신규 키 수 | 예시 |
|---|---|---|
| Q4 답변 (4 분기 × 3-4 옵션) | ~16 | `Q4-CRED:mfa_token_reuse`, `Q4-RANSOM:backup_destroyed` |
| Q5 답변 (4 분기 × 3-4 옵션) | ~16 | `Q5-CRED:non_korean_ip`, `Q5-MISCFG:public_change` |
| Q6 답변 (4 분기 × 3-4 옵션) | ~16 | `Q6-RANSOM:ransom_note_found`, `Q6-INSIDER:trace_deletion` |
| **조합 부스트** (특정 답변 조합 시 추가 점수) | ~8 | `(Q4-CRED:mfa_token_reuse + Q5-CRED:non_korean) → PHISH +15` |
| **총** | **~56 키** | weights.json의 decision_tree_answers 가 25 → 81 |

### 가중치 부여 원칙

1. **단위 5 정책 유지** (5/10/15/20/25/30/35)
2. **Q1·Q2** — 일반 시그널 (+5~25)
3. **Q3·Q4** — 사고유형 변별 시그널 (+15~30)
4. **Q5·Q6** — 확정·복합 시그널 (+20~35)
5. **조합 부스트** — 의외성·강한 시그널 (+10~20)
6. **학술 근거 부착** — 각 키의 source 필드 + `[ISO 27035-1:2023 Assess & Decide]` 태그

## 6. 학술 변호 매핑 (캡스톤 평가 대비)

| 우리 단계 | 학술 표준 정합 |
|---|---|
| Q1 사고 인지 경로 | **NIST SP 800-61r2 §3.2 표 3-2** (Sources of Precursors and Indicators) |
| Q2 직접 정황 | **KISA 2025-08 제2장** 초기 대응 점검표 6항목 |
| Q3 추가 패턴 | **KISA 제3장** 사고유형별 대응 — 1차 분류 |
| **Q4 증거 무결성·시간축** | **NIST SP 800-86 §3** Volatility Hierarchy + 의료 감별진단 "현재 상태" |
| **Q5 영향 범위·행위자** | **ISO/IEC 27035-1:2023 Assess & Decide** (impact assessment) + 의료 "전파 범위" |
| **Q6 후속 시그널·의도** | **AWS Detective Profile-by-Profile pivot** + 의료 "사후 변화 관찰" |
| T_evaluate | NIST 800-61r2 §3.2.4 incident analysis 종합 |
| 실시간 신뢰도 게이지 | 의료 감별진단 "diagnostic confidence" |
| 답변별 영향 미리보기 | 결정성 100% 학술 변호 + AWS Detective scope time |
| 동적 분기 | 의료 감별진단 (Differential Diagnosis) 점진적 가설 좁히기 |

### 캡스톤 평가 변호 카드

> 본 시스템의 결정 트리는 **NIST SP 800-61r2 §3.2 Triage** 의 6단계 indicator-driven 진단 흐름을 한국 클라우드 환경으로 특화한 구현이며, **의료 감별진단**(Differential Diagnosis) 의 점진적 가설 좁히기 방법론을 결합하여 **결정성 100%** + **신뢰도 게이지** + **동적 분기**로 학술적 정합과 사용자 경험을 모두 충족한다.
