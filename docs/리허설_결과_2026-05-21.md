## 🟡 발견 이슈 — UI/UX 개선 후보 (내일 작업 인풋)

### 🟡 #1 — UNCLASSIFIED 케이스로 직접 V-2 진입 시 매처 미작동

**재현**: V-1 Step 1 까지만 한 상태 (incident_type=UNCLASSIFIED) → V-2 직접 진입해 로그 업로드

**관찰**:
- `matchers.py::_REGISTRY` 에 (csp, "UNCLASSIFIED") 키 없음
- 결과: `matched=0, byTarget={}`
- 그 결과 V-4 gap detection → `completionRate=0%` 로 무의미한 응답

**기대 동작 옵션**:
- (A) V-2 화면이 `incident_type === "UNCLASSIFIED"` 일 때 업로드 비활성화 + "Step 2 Discovery 를 먼저 완료해 주세요" 안내
- (B) UNCLASSIFIED 일 때는 모든 사고유형 매처를 순회해 가장 많이 잡히는 것 사용 (자동 추론)
- (C) UNCLASSIFIED 일 때 업로드 자체는 허용하지만 V-4 갭 결과에 "사고유형 미확정 — Step 2 결과 후 재산정 필요" 안내

**우선순위**: 🟡 (정상 흐름은 Step 2 → V-2 이지만 사이드바 클릭으로 우회 가능)

### 🟡 #2 — incident_type 변경 후 raw_events.matched_target_id 재산정 안 됨

**재현**:
1. UNCLASSIFIED 로 케이스 생성 → V-2 업로드 (matched=0)
2. PATCH `incident_type=PRIVILEGE_ESCALATION`
3. V-4 갭 감지 → 여전히 `completionRate=0%`

**원인**: `LogIngestor` 가 업로드 시점의 incident_type 으로 매처 호출. PATCH 후 재실행되지 않음.

**기대 동작 옵션**:
- (A) PATCH /api/cases 가 incident_type 변경을 감지하면 백그라운드로 `LogIngestor.rematch_case(case_id)` 트리거
- (B) V-2 화면에서 "사고유형 변경 감지 — 매칭 재산정" 버튼 표시
- (C) V-4 갭 감지 호출 시 매칭이 비어있고 incident_type 이 확정되어 있으면 자동 rematch

**우선순위**: 🟡 (이슈 #1 과 함께 발생, A 옵션이 가장 깔끔)

### 🟡 #3 — V-8 사후 검증이 PE 정합 케이스에서 CONSISTENT 인데 후보 풍부

**재현**: PE 확정 케이스 + Sysdig 시나리오 → V-8 `/validate-incident-type` 호출

**관찰**:
```
status      : CONSISTENT
candidate_types (8건):
  PRIVILEGE_ESCALATION = 2/2 (1.0) ← 확정 정합
  CREDENTIAL_THEFT     = 4/5 (0.8) ← 강한 부 사고유형 시그널
  DATA_EXFILTRATION    = 1/2 (0.5)
  INSIDER_THREAT       = 2/4 (0.5)
  ...
```

CT 0.8 / DE 0.5 시그널이 강한데도 REVIEW_NEEDED 가 아니라 CONSISTENT 로 분류.

**기대 동작**:
- REVIEW_NEEDED 임계값을 검토 (현재 score_ratio 동률 조건만? 0.8 도 트리거 후보)
- 또는 후보 사고유형 0.5 이상이 N개 이상이면 REVIEW_NEEDED

**우선순위**: 🟢 (현재 CONSISTENT 도 UI 카드 자체는 숨겨져 시연엔 무해. 다만 V-8의 가치가 약해 보일 수 있음)
