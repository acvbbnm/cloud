## v7 주요 변경 (vs v6)

| 영역 | v6 | **v7** |
|---|---|---|
| 논문 등장 시점 | 슬라이드 5 (어둠 셋 모두 끝난 후) | **슬라이드 2** (출발지 = 현장) |

| 눈뜨기 표현 | 슬라이드 2·3·4·7·10·11 (8회 반복) | **슬라이드 1·11 두 곳만** (도입+마무리) |

| 카드 변주 | 슬라이드 2·3·4 동일 패턴 (눈 가리는 / 뜨게 하는) | **각 슬라이드 다른 키워드** (막힘 / 분산 / 결정 회피) |

# 슬라이드 7 / 11 — AS-IS  ·  AWS Detective 정밀 비교

**Bridge**:
> "그런데 — *왜 새로 만들어야 했나*? 시중에 좋은 도구가 이미 많은데."

**시각**: 좌측 AWS Detective 화면 캡처 / 우측 AI Sherpa 화면 — 핵심 차이 6개 비교

### 왜 AWS Detective 인가
우리 벤치마크 분석 (`docs/벤치마크_클라우드_사고조사.md`) 에서 *가장 유사한 도구* 로 명시된 18 도구 중 하나. 그래프 기반 entity-finding 으로 우리와 컨셉 인접. *가장 강한 경쟁자* 와의 비교가 가장 설득력 있음.

### 비교 표

| 항목 | **AWS Detective** | **AI Sherpa** |
|---|---|---|
| 진입점 | GuardDuty Finding 클릭 *필수* | **정황만으로 가능** (UNCLASSIFIED) |
| 단서 정의 | finding (이미 사고유형 매핑됨) | **raw observable** (IP·user·time) |
| 사고유형 분류 | ATT&CK Tactic 자동 매핑 (사후) | **단서 누적 → 자연 발현** |
| CSP 지원 | AWS 전용 | **NCP/NHN 특화** |
| 동작 환경 | SaaS (외부 API 필수) | **폐쇄망 그대로** |
| 학술 변호 | finding 결과만 | **단서마다 KB 청크 + 학술 인용** |

### 도입 이유 (어필 포인트)

```
왜 AWS Detective 를 따르지 않았나?

  ① "Finding 클릭으로 시작" — 알람 안 떠도 *정황·제보·정기감사* 로 진입 가능해야
  ② "ATT&CK = 단서" — 시스템이 답을 미리 내려놓으면 *수사관 추론 가려짐* (논문 발견 ③)
  ③ "AWS 전용" — 국내 NCP·NHN 은 사각지대 (논문 향후 i)
  ④ "SaaS" — 국내 폐쇄망 환경에 부합 X (논문 향후 iii)

→ Detective 는 *AWS·SaaS 환경* 에 최적화. 우리 *국내·폐쇄망·미알람* 현장에 부합 X.
→ AS-IS 모방 ≠ 우리 환경에 답.
```
