# 전체 흐름 — 영웅의 여정 매핑

```
                    ┌─────────────────────────────────────────────────┐
                    │           영웅의 여정 (Hero's Journey)           │
                    └─────────────────────────────────────────────────┘

[1단계 평범한 세계]   슬라이드 1·2     검은 화면 + 어두운 맵 등장
                                       (수사관의 가려진 시야)

[2단계 모험의 부름]   슬라이드 3       그래프 — "측정된 어려움"
                                       (현장이 부른다)

[3단계 길잡이 등장]   슬라이드 4·5     우리 논문 + 어두운 맵 전체 점등
                                       (우리 자신이 길잡이)

[4단계 첫 관문]       슬라이드 6       셰르파 컨셉 + 5계층
                                       (시스템 개요)

[5단계 시련·동맹]     슬라이드 7·8     AS-IS 대비 TO-BE + 결정성
                                       (왜 다른 길을 가야 하는가)

[6단계 시련의 정점]   슬라이드 9       라이브 데모
                                       (실제로 작동하는가)

[7단계 보상·확장]     슬라이드 10      확장성
                                       (이것은 시작에 불과)

[8단계 귀환]          슬라이드 11      정상에서
                                       (메시지 전달 후 무대 아래로)
```

**공명/대조의 진동** (두아르테 — Resonate):

```
What is (어둠)     ↔    What could be (시야)        ← 슬라이드 2~5
What is (AS-IS)    ↔    What could be (TO-BE)       ← 슬라이드 6~8
What is (정황)     ↔    What could be (사고 전모)   ← 슬라이드 9 데모
```

## 컬러 팔레트 (우리 시스템 UI 와 일관)

```
배경 (다크):     #0a0c10
배경 (밝음):     #f8fafb (논문 표지·표·차별점 슬라이드용)

본문 텍스트:     #e6e9f0
보조 텍스트:     #9aa3b2
강조 텍스트:     #5EEAD4   (청록 — 빛)

점등 빛:         radial gradient ( #FBBF24 → #5EEAD4 → transparent )
강조 위험:       #E63B3B   (Mandiant 통계·결정성 강조)
사고유형 8색:    시스템 컴파스와 동일 (자격증명 #5BA3F0, 랜섬 #E63B3B 등)
```

## 폰트

```
헤더 (한 줄 주장):   Pretendard Black     40~48pt
본문 텍스트:         Pretendard Bold      24~28pt
보조 (인용·통계):    Pretendard Regular   18~22pt
모노 (식별자·코드):  JetBrains Mono       18~24pt
```

> 가와사키 30pt 룰 준수 — 본문 24pt 이상.

## 적용 원칙

1. **앨리 주장-증거** — 슬라이드 상단 = 완성된 *문장*, 하단 = *시각만*
2. **레이놀즈 젠** — 1 슬라이드 = 1 메시지. 텍스트 최소화.
3. **글랜스 테스트** — 3초 안에 *주장* 이 읽혀야 함.

# 슬라이드 4 / 11 — 어두운 맵 + 세 번째 영역 점등

## 한 줄 주장

> **수사관의 눈을 가리는 것 ③  ·  분석은 도와주되, 결론은 내가 내린다**

## 시각 레이아웃

세 영역 모두 점등 — 맵의 70% 가 보이는 상태.

```
┌─────────────────────────────────────────────────────────────────┐
│ [헤더] 수사관의 눈을 가리는 것 ③  ·                              │
│         "분석은 도와주되, 결론은 내가 내린다"                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   📜 → 📦                🔗 ✓                  🌫 → 🧭          │
│   (점등 ②, 유지)         (점등 ①, 유지)        (점등 ③)         │
│                                                                 │
│   적재함                  단서 chain             컴파스 + 단서 길  │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│  로그아웃  |  4/11  |  KCC 2026                                  │
└─────────────────────────────────────────────────────────────────┘
```

**우측 통계 카드** (점등 후):

```
자동화 희망 작업 (다중 응답):
   ATT&CK 매핑      5 / 8  ← 최다
   타임라인 정리    4 / 8
   IOC 추출         3 / 8
```

**우측 도구 카드** (점등 + 5초 후):

```
👁  Evidence Tree + 사고유형 컴파스
   단서 = raw observable
   ATT&CK 기법 = *해석 검증용 hint*
   사고유형 = *자연 발현*
```

## 애니메이션 시퀀스

```
0:00  슬라이드 등장 (영역 ①·② 점등 상태 유지)
0:05  헤더 + "③" 강조
0:25  우측 영역에 radial 점등
0:35  🌫 흩어진 단서 점들이 → 길로 정렬되는 animation
0:50  우측 도구 카드 fade in
1:05  종료
```

## 발표자 멘트 (강조 부분 굵게)

> "세 번째 — *가장 중요한 발견* 이었습니다.
>
> 실무자가 가장 자동화를 원하는 건 ATT&CK 매핑.
> 흥미로운 점 — 가장 *어려운 작업* 인 *원인 분석 자체* 의 자동화는 우선순위가 아니었습니다.
>
> 다시 말하면 — **분석은 도와주되, 결론은 내가 내린다**.
>
> *(우측 점등)*
>
> 그 눈을 뜨게 해주는 세 번째 도구 — *Evidence Tree + 컴파스*.
> 단서는 raw 신호, ATT&CK 기법은 hint, 사고유형은 *자연 발현*.
>
> *수사관의 추론* 이 — 일의 중심에 옵니다."
