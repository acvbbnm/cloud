## 3. 시연 세일링 포인트 — 3대 메시지

### 🎯 메시지 1: "AI는 판단하지 않는다 — 결정성 100%"

**왜 차별점인가**:
- 시중 침해대응 도구는 AI 추론 결과를 그대로 사용자에게 결정으로 제시
- 환각·블랙박스 문제 → 수사관이 책임지기 어려움
- 우리: **결정 트리 + 정적 가중치(weights.json) + 정적 매핑(rules.json)** 으로 모든 판단 결정성 100%
- AI(LLM)는 RAG 검색·요약·제안만 — 항상 출처 [N] 인용 + "최종 판단은 수사관" 문구

**시연 포인트**:
- V-1 Step 3 결정 트리: 같은 답변 → 항상 같은 점수 (재실행 시연)
- V-8 셰르파: 답변에 출처 칩 (ATTACK / PLAYBOOK / CSP_DOC / CASE_DB)
- V-8 사후검증: tactic → incident_type 정적 매핑 (LLM 미사용)

### 🎯 메시지 2: "외부 표준 7종 명시 인용 — 학술 변호 가능"

**왜 차별점인가**:
- 시중 도구는 "왜 이렇게 분류?" 질문에 답 못함
- 우리 모든 분류·점수·룰에 학술/표준 명시 인용:
  1. **MITRE ATT&CK Cloud Matrix v14** — 매핑 룰 74개의 technique_id
  2. **Google Cloud Threat Intel — Cloud Log Configurations** — 1.x 카테고리
  3. **KISA 침해사고 분석절차 안내서 (제2010-8호)** — Phase + 초기대응 점검표
  4. **NIST SP 800-86 § 3.1** — 휘발성 계층 우선순위
  5. **ISO/IEC 27037:2012** — 디지털 증거 처리
  6. **CSA Top Threats to Cloud Computing 2024** — 사고유형 분류
  7. **Verizon DBIR 2024** — 가중치 통계 근거

**시연 포인트**:
- V-1 Step 4 가이드: 우측에 7 표준 출처 칩
- V-1 Step 4 신규 (PR #9): 각 시드 행에 MITRE 기법 칩 + 콘솔 메뉴 hint + CLI cmd
- 모든 attack_rule 에 `source` 필드 — 발표 시 코드 보여주기 가능

### 🎯 메시지 3: "V-1 ↔ V-8 양방향 검증 — 사용자 결정 + AI 보완"

**왜 차별점인가**:
- 시중 도구는 단방향: AI 가 분류 → 사용자 통보
- 우리: **수사관이 결정 → Layer 2 분석 → V-8 사후검증이 보완**
- 청사진 §원칙 5 "Layer 2 매핑 결과로 V-1 결정 보완"

**시연 골든 케이스 (Sysdig 8min Killchain)**:
1. V-1 Step 3 결정 트리 → 수사관 PE 확정
2. V-2~V-3 로그 분석 → 13 events 매핑 (10/13, 77%)
3. V-4 갭 감지 → completionRate 100%
4. V-8 사후검증 자동 호출 → "PE 확정은 정합. **단 CT·DE 증거도 발견** (suggested)"
5. 수사관 채택 → PATCH `secondary_incident_types`

→ **AI 가 인사이트 보완, 결정은 수사관** — 양방향 흐름의 명확한 시연
