## 5. priority 부여 기준 — NIST SP 800-86 휘발성 계층

NIST 800-86 § 4.1.1 "Order of Volatility" 는 증거를 휘발성 순으로 수집할 것을 권고한다.

| 휘발성 등급 | 일반 예시 | AI Sherpa priority |
|---|---|---|
| 1. 즉시 휘발 | CPU/메모리, 네트워크 세션 | 본 시스템 범위 외 (호스트 포렌식 도구 영역) |
| 2. 짧은 휘발 | 로그인 세션, 임시 파일 | 9~10 (인증 이벤트) |
| 3. 중간 휘발 | 시스템 로그, 보안 로그 | 6~9 (권한 변경, API 호출) |
| 4. 낮은 휘발 | 보존 정책 적용 영구 저장 | 4~6 (객체 스토리지, 인프라 구성) |
| 5. 영구 | 백업, 아카이브 | 1~3 (콜드 스토리지) |

→ `collection_targets.priority` 의 1~10 점수가 휘발성 + 증거 가치 + 접근 어려움의 가중합으로 부여됨.

## 6. 무결성 — ISO/IEC 27037:2012 매핑

ISO 27037 § 5 "디지털 증거 처리 절차" 의 4단계와 본 시스템 구현 매핑:

| ISO 27037 단계 | AI Sherpa 구현 |
|---|---|
| § 5.2 식별 (Identification) | Layer 0 `CollectionGuide.generate()` — 사고유형·CSP 별 필요 로그 식별 |
| § 5.3 수집 (Collection) | Layer 1 `LogIngestor.ingest()` — 파일 업로드 + `action_logs` 자동 적재 |
| **§ 5.4 획득 (Acquisition)** | **`raw_events.sha256`** SHA-256 해시로 파일 단위 무결성 검증 |
| **§ 5.5 보존 (Preservation)** | **`raw_events.raw_json`** TEXT 컬럼에 원본 그대로 보존 (정규화 전 사본) |
| § 5.6 문서화 | `action_logs` 테이블 — ACCEPT / REJECT / EDIT_REPORT / FINALIZE_REPORT / EXPORT_REPORT 감사 추적 |

**핵심 결정**: 정규화 후 데이터(`ocsf_events`, `attack_events`)는 파생 데이터로, 원본 `raw_events.raw_json` 이 법적·학술적 증거. 정규화·매핑 결과를 의심하더라도 raw_json + SHA-256 으로 원본 검증 가능.

## 7. MITRE ATT&CK 매핑 — Cloud Matrix v14

`data/attack_rules/rules.json` 22룰 (NCP 11 + NHN 11) 의 technique_id 가 ATT&CK Cloud Matrix v14 의 어느 전술·기법인지.

### 전술별 분포

| 전술 (Tactic) | 룰 수 | 대표 기법 |
|---|---|---|
| Initial Access | 2 (R-NCP-001, R-NHN-001) | T1078.004 (Valid Accounts: Cloud Accounts) |
| Persistence | 7 | T1098.001 (Account Manipulation: Additional Cloud Credentials), T1136.003 (Cloud Account Creation) |
| Credential Access | 1 (R-NCP-006) | T1552 (Unsecured Credentials) |
| Privilege Escalation | 3 | T1098 (Account Manipulation) |
| Lateral Movement | 1 (R-NCP-002) | T1021 (Remote Services) |
| Exfiltration | 2 | T1537 (Transfer Data to Cloud Account), T1567 (Exfiltration Over Web Service) |
| Impact | 6 | T1485 (Data Destruction), T1489 (Service Stop), T1531 (Account Access Removal) |

→ ATT&CK Cloud Matrix 의 9개 주요 전술 중 **7개 전술 커버** (Defense Evasion, Discovery, Collection 미커버).

### 출처 명시

`attack_rules/rules.json` 의 각 룰에 `source` 필드 — 실 raw 로그(`activity_logs_full.json`, `nhn_activity_logs.json`) 의 어느 시점·계정에서 패턴이 검증됐는지 + MITRE ATT&CK 공식 ID 참조.

## 9. 향후 확장 계획

### Phase A: 시드 5건 → 50건 확장 (PROGRESS.md "다음 할 일")

기존 `collection_targets/{csp}_{type}.json` 5건 형식을 **9 카테고리 × 5 사고유형 × 2 CSP 매트릭스**로 재구성. 각 target_id 에 다음 메타 추가:

```json
{
  "target_id": "CT-NCP-AUTH-LOGIN",
  "incident_type": ["CREDENTIAL_THEFT", "PRIVILEGE_ESCALATION"],
  "csp": "naver",
  "category": "1.5.1",
  "category_name": "클라우드 인증 - 인증 기록",
  "kill_chain_phase": "초기 침투",
  "rationale": {
    "google_cloud": "1.5.1 (인증 기록)",
    "mitre": "T1078.004",
    "iso27037": "§5.4 (인증 증거 무결성)",
    "nist800_86_volatility": "중간 (서버 로그)",
    "use_case": "비국내 IP·비업무시간 로그인 탐지"
  }
}
```

### Phase B: V-1 위저드 입력 확장 (NIST SP 800-61 기반)

현재 7필드 → 카테고리별 시스템 환경 5종:
- 자격증명 환경 (MFA, AccessKey, SSO)
- 데이터 환경 (Object Storage 사용, 민감 분류, 암호화)
- 네트워크 환경 (VPC, ACG/SG, 공인 IP, VPN)
- 감사 환경 (Tracer/Trail 활성, 보존 기간)
- 인증 환경 (IAM 멤버 수, 역할 그룹 수, 관리자 비율)

각 입력값이 `priority` 가중치에 실제 영향 (예: MFA 미적용 → CT-AUTH-MFA priority 10 부스팅 + 안내 추가).

### Phase C: 한국 표준 본문 통합 (KISA PDF 입수 후)

§ 8 참조.
