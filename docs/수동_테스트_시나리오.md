# dev2 수동 테스트 시나리오

> 회의 직전 직접 클릭하면서 검증할 흐름. 5계층(L0→L4) × 3 사고유형 시나리오 + dev2 신규 기능 점검.
>
> **시작 전 확인**:
> - 백엔드: http://127.0.0.1:8000/api/health → `{"status":"ok"}`
> - 프론트: http://localhost:5173
>
> **소요 시간**: 시나리오 A 전체 ~15분 / 시나리오 B·C 각 ~10분 / dev2 신규 기능 ~10분 = 합 45~50분

## 🎯 시나리오 A — NCP 자격증명 탈취 (가장 임팩트 큰 시연)

**스토리**: NCP attack-sim 계정이 MFA 미적용 상태에서 외부 IP로 침투 → 권한 변경 → Server Console 접근 → Object Storage 유출

### 단계 A-1: 사고 접수 (V-1 Setup)

1. http://localhost:5173 → **V-1 Setup**
2. **Step 0** — CSP 선택: **Naver Cloud (NCP)**
3. **Step 1** — 사고 유형: **🔑 자격증명 탈취 (CREDENTIAL_THEFT)**
4. **Step 2** — 시스템 구성:
   - **사고 기본** 탭: 심각도 `Critical`, 인지 일시 그대로
   - **CSP 특화** 탭: 사용 서비스 `Object Storage` 체크, 공인 IP `있음 (서버 직접 할당)`, Activity Tracer `활성화 (정상 수집 중)`
   - **🛡 보안 정책** 탭: MFA `미적용` ← 핵심 / 나머지는 기본값
5. **다음** 클릭 → 케이스 생성됨 (caseId 토스트 표시)

### 단계 A-2: V2 가이드 매트릭스 (Step 3) — dev2 핵심 기능

6. Step 3 도달 시 **🆕 표준 기반 (v2)** 토글 클릭
7. 상단 **🛡 MITRE Kill Chain 12 전술 안내** 카드 펼치기 → 12 전술 중 5개 강조 확인
8. **📋 리스트** ↔ **🗂 매트릭스** 토글로 두 뷰 모두 확인
9. 매트릭스에서 **빨강 P13 셀** (1.5.1 인증) 클릭 → 우측 **KB 패널** 펼침
   - 🧭 왜 필요한가
   - **📥 어떻게 수집하나** (NCP Cloud Activity Tracer 4단계 + CLI)
   - 🎯 활용 사례 4건
   - 📑 외부 표준 5건 (Google·KISA·MITRE·NIST·CSA)
10. KB 패널의 **[Google]** 카드 클릭 → 외부 페이지 새 탭 이동 확인
11. 좌측 항목 체크박스 클릭 → 헤더 `0/11 → 1/11` 갱신 확인
12. 브라우저 새로고침 → 체크 상태·매트릭스 뷰 유지 확인 (localStorage)
13. 하단 **V-2 로그 수집 진행 →** 클릭

### 단계 A-3: 로그 업로드 (V-2 Logs)

14. **로그 파일 업로드** → `backend/data/synthetic/ncp_none.json` 드래그&드롭 (16건 raw)
15. 업로드 완료 후 통계 패널 확인: 총 16건 / 매칭 N건 / 미매칭 M건
16. **이벤트 미리보기 테이블**에서 actor=`attack-sim`, sourceIp=`115.91.214.5` 확인
17. 어느 행 클릭 → 우측 raw JSON 펼침 확인

### 단계 A-4: OCSF 정규화 (V-3)

18. 사이드바 V-3 클릭
19. **정규화 실행** 버튼 → 16건 → OCSF 16건 변환률 ~100%
20. 테이블에서 `actor_user_name`, `src_endpoint_ip`, `activity_name`, `status_code` 컬럼 확인
21. 매칭 안 된 행은 `unmapped_raw` 객체 보유

### 단계 A-5: ATT&CK 매핑 (V-6)

22. 사이드바 V-6 → **ATT&CK 매핑 실행** 클릭
23. OCSF 16건 → ATT&CK 이벤트 N건 (룰 22건 적용)
24. `T1078.004 (Valid Accounts)`, `T1098.001 (Add Cloud Creds)` 등 기법 표시
25. 매트릭스 형태 시각화 (Tactic × Technique) 확인

### 단계 A-6: 갭 감지 (V-4)

26. 사이드바 V-4 → **갭 감지 실행**
27. 결과: `gap_type=NONE` 또는 `COLLECTION` (시나리오에 따라)
28. `completionRate`, `recommendation`, `missing[]` 확인
29. 변형 시나리오: `ncp_collection.json` 업로드 시 IAM-003 누락 → COLLECTION 갭 발생

### 단계 A-7: 수사 보드 (V-5)

30. 사이드바 V-5 → 자동 매핑된 ATT&CK 이벤트들이 노드로 표시
31. 새 노드 추가 (수동): 좌측 패널 → 노드 이름 입력
32. 노드 드래그로 위치 이동
33. 노드 두 개 연결: 첫 노드 클릭 → 두 번째 노드 클릭 → 엣지 생성 UI
34. 노드 우클릭 → REJECTED 변경 (action_logs 적재 트리거)

### 단계 A-8: 보고서 (V-7)

35. 사이드바 V-7 → **보고서 초안 생성** 클릭 → 8 섹션 자동 생성
36. 섹션 텍스트 수정 (예: overview 문장 추가)
37. **저장** 후 우측 **액션 로그 패널**에 EDIT_REPORT 표시 확인 (새 API `/api/actions`)
38. **DOCX 내보내기** 클릭 → ~36KB 파일 다운로드
39. DOCX 열어서 한국어 표/이미지/섹션 8개 모두 정상 렌더링 확인

### 단계 A-9: AI 셰르파 채팅 (V-8)

40. 사이드바 V-8 또는 우하단 플로팅 셰르파 버튼
41. 헤더에 `engine: ollama / llama3.1:8b · rag: chromadb (66 청크)` 확인
42. 질문 1: "NCP 환경에서 자격증명 탈취 사고가 발생했을 때 인증 로그는 어떻게 수집하나요?"
43. ~100초 후 한국어 응답 + `[1][2][3]` 출처 인용
44. 우측 KB 패널에서 출처 클릭 → 외부 페이지 이동
45. 응답 마지막에 `※ 최종 판단은 수사관께서 직접 수행해 주세요.` 면책 문구 확인

## 🎯 시나리오 B — NHN 데이터 유출 (민감정보 + 보존 기간 단축)

**스토리**: NHN 데이터 분석가 계정이 컨테이너 메타데이터 공개로 변경 → 8.9GB 다운로드 → 자격증명 흔적 제거

### 입력 (Step 1~2)
- CSP: **NHN Cloud**
- 사고유형: **📤 데이터 유출 (DATA_EXFILTRATION)**
- 심각도: `Critical`
- CSP 특화: 사용 서비스 `Object Storage` + `Cloud DB` 체크
- 🛡 보안 정책:
  - **IAM 계정수: 75** (modifier m-006 트리거)
  - **감사 로그 보존: 30일** (modifier m-007 → 환경 경고)
  - **민감 데이터: 있음 (개인정보·민감정보)** (modifier m-008)

### 확인 포인트
- Step 3 매트릭스 **빨강 P13 셀 = 1.4 파일 스토리지** (Object Storage +2 + 민감정보 +2 + Collection +1 = 누적 +5)
- 환경 경고 카드 빨강 표시: `⚠ CT-RETENTION-WARNING P9 — 감사 로그 보존 기간 부족`
- 1.7 Stealth phase에 P11 표시 (메타 로그 +1)
- 로그 업로드: `backend/data/synthetic/nhn_none.json` (16건, NHN)
- V-6 ATT&CK: T1530, T1567 가능

### V-8 질문
> "민감정보가 포함된 클라우드 환경에서 데이터 유출 사고 발생 시 어떤 절차로 대응해야 하나요?"
> → PLAYBOOK-EXFIL-001 ~ 002 인용 응답

  - **SSO: 있음 (외부 IdP 연동)** (m-011)
  - 멀티 클라우드: `csp=all` 선택 시 자동 인식 (m-010)

### 확인 포인트

## 🛠 dev2 신규 기능 집중 점검

| 기능 | 화면 | 확인 |
|---|---|---|
| **V2 가이드 토글** | V-1 Step3 | 기존 v1 (단순 체크리스트) ↔ v2 (Kill Chain 매트릭스) 즉시 전환, localStorage 영속화 |
| **KB 인라인 패널** | V-1 Step3 매트릭스 | 셀 클릭 → 우측 sticky 패널. 6개 섹션(왜·어떻게·사례·근거·출처·CSP 매핑) |
| **수집 절차 (collection_steps)** | KB 패널 📥 섹션 | NCP/NHN 별 4단계 콘솔 절차 + CLI 힌트 |
| **체크박스 + 진척률** | V-1 Step3 | 항목별 체크 → 헤더 `2/11 수집 완료` 갱신. 새로고침해도 유지 |
| **Phase 안내 카드** | V-1 Step3 상단 | 펼치면 12 전술 한국어/영문/정의. 현재 가이드 포함 단계는 청록 강조 |
| **환경 modifier ↑+N 배지** | 매트릭스 셀 | Step2 입력 → 매트릭스 셀에 `↑+3` 부스팅 표시 (호버 시 사유) |
| **3축 매트릭스 검증** | docs | 15셀 운영급 평가 — 🟢 15 / 🟡 0 / 🔴 0 |
| **/api/actions 액션 로그** | V-7 우측 패널 | EDIT_REPORT, EXPORT_REPORT, REJECT 등 실시간 표시 |
| **외부 표준 6종 출처 클릭 이동** | KB 패널 📑 | Google 블로그, MITRE 페이지, KISA 등 새 탭 이동 |

## 🐛 회의에서 짚으면 좋을 P1 (현재 한계)

1. **chat 응답 100초** — CPU + llama3.1:8b 환경. 회의 시연에서는 미리 한 번 데우거나 GPU 머신에서 진행 권장.
2. **PDF export 미구현** — DOCX만 지원. weasyprint 6시간 작업.
3. **새 노드 default = CONFIRMED** — PENDING 단계 없이 즉시 CONFIRMED. ACCEPT 액션이 자연스럽게 발생할 일이 없음 (의도 vs 개선 여지 논의).
4. **L3 RAG 키워드 fallback** — 한국어 의미 검색 점수가 낮으면 키워드로 떨어짐. 한국어 특화 모델(`ko-sroberta-multitask`) 교체 검토.
