## 1. 시스템 개요

### 1.1 정의
- **프로젝트명**: AI Sherpa — 국내 멀티 클라우드 침해사고 분석 시스템
- **타깃 환경**: 폐쇄망 단일 데스크톱 (오프라인, SNF-01)
- **타깃 CSP**: NAVER Cloud (NCP) + NHN Cloud
- **핵심 원칙**: AI는 판단하지 않는다 — 검색·요약·제안만, 수사관이 결정

### 1.2 5계층 데이터 모델

| 계층 | 책임 | 핵심 클래스 (설계서) | DB 테이블 |
|---|---|---|---|
| Layer 0 사고 접수 | 케이스 메타 + 단서 추론 + 수집 가이드 | `IncidentCase`·`CollectionGuide`·`CollectionTarget`·`IncidentTypeKnowledge` | `incident_cases`·`collection_targets` |
| Layer 1 로그 수집 | 원본 로그 적재 + SHA-256 | `LogIngestor`·`RawEvent`·`IngestionStats` | `raw_events` |
| Layer 2 분석 | OCSF 정규화 + ATT&CK 매핑 + 갭 감지 | `OCSFNormalizer`·`AttackMapper`·`GapDetector` | `ocsf_events`·`attack_events`·`gap_results` |
| Layer 3 AI 셰르파 | RAG 검색 + LLM 응답 | `AISherpa`·`RAGRetriever`·`LLMEngine`·`KnowledgeBase` | (ChromaDB 별도) |
| Layer 4 보드·보고서 | 체인 노드·엣지 + 보고서 | `InvestigationBoard`·`ChainNode`·`ChainEdge`·`ReportGenerator` | `chain_nodes`·`chain_edges`·`action_logs` |

## 3. V-1 Step 3 — Evidence Tree (★ 풀체인)

### 3.1 패러다임

dev3의 정적 결정 트리(Q1→Q2→Q3)를 **단서 기반 동적 베이지안 추론** (Bottom-up Abductive) 으로 전환.

```
[Cold-start] uniform 1/8 (Jaynes 1968)
   ↓ 정찰 단서 (NIST SP 800-86 §4.1)
[Zone 1 광범위 탐색]
   ↓ IG 추천 누적 (Shannon 1948)
   ↓ depth ≥ 3 + boss_lk ≥ 0.30
[Zone 2 사고유형 chain 구체화]
   ↓ advance-stage
[Multi-Stage chain] CRED → PRIV → DATA
   ↓ BridgeToBoardCard
[Evidence Board V-5]
```

### 3.4 IG 추천 — NextCluePanel

> 학술 근거: Shannon 1948 *A Mathematical Theory of Communication* — Information Gain = KL divergence

| 항목 | 내용 |
|---|---|
| 알고리즘 | `core/intake/info_gain.py:information_gain()` |
| 수식 | `IG = H(P) − P(c=1)·H(P\|c=1) − P(c=0)·H(P\|c=0)` (양·음성 evidence 모두 marginalization) |
| 후보 풀 | 143 단서 카탈로그 전체 (이미 채택된 단서 + UNCLASSIFIED 제외) |
| K 결정 (동적) | `H ≥ 2.5` → 5개 / `H ≥ 1.5` → 3개 / `H < 1.5` → 2개 (entropy 기반) |
| 정렬 | IG 내림차순 |
| 응답 필드 | `candidates[].{candidate_id, clue_key, label, expected_info_gain, rationale, outcome_flags, techniques}` |
| UI 표시 | IG 정규화 게이지 + ATT&CK 기법 chip + outcome_flags badge + ▼ 추천 이유 expand |

### 3.5 단서 채택 — expand_tree (풀체인)

```
사용자 액션:  IG 후보 클릭 / 직접 입력 / 로그 분석 결과
   ↓
프론트:   useClueTreeStore.expand({caseId, parent_node_id, clue_key, source})
   ↓
[POST /api/clue-tree/expand]
   ↓
백엔드: clue_tree_service.expand_tree()
   1. _load_case + _load_tree_from_case
   2. catalog[clue_key] 조회 → weights / has_weights 검증
   3. likelihood 계산:
      · TRIAGE_MODE=bayes_net   → bayes_net.clue_likelihood_via_bn(clue_key)
      · 그 외                   → weights_to_likelihood(weights)
        (Laplace add-k=2, SMOOTHING=2.0)
   4. posterior_after = bayes_update(posterior_before, likelihood)
      · raw[h] = posterior[h] × likelihood[h]
      · normalize: 합 = 1
      · apply_robust_floor(eps=0.08, Berger 1985)
        → 각 가설 ≥ 1% floor 보장 (단일 가설 99% 쏠림 차단)
   5. append_clue_node(tree, parent_id, clue_key, ..., posterior_before, posterior_after)
      · score_delta = posterior_after − posterior_before
      · node.depth = parent.depth + 1
      · tree.current_leaf_id = new_id
   6. confidence = evaluate_confidence(posterior_after, depth=node.depth)
      · depth 별 차등 임계값 (Phase K 후속)
        depth < 3  : 절대 도달 불가 (auto_confirm 1.01)
        depth = 3  : primary_p ≥ 0.80 + gap ≥ 0.30
        depth = 4  : ≥ 0.75 + 0.25
        depth ≥ 5  : ≥ 0.65 + 0.20 (표준)
   7. accepted = _collect_accepted_keys(tree)
   8. candidates = _build_candidates(posterior, exclude=accepted)
      · entropy 기반 K (5/3/2)
      · pick_top_candidates(use_marginalization=True)
   9. set_candidates(tree, new_leaf_id, candidates)
  10. heal_tree_invariants(tree)
  11. _save_tree_to_case (DB)
  12. _build_response(tree)
   ↓
응답 (Phase M·N.4 확장 필드):
   {tree, posterior_current, confidence, candidates, path,
    zone (1|2), attack_chain[Top 3], core_clue_likelihood,
    regress_suggested, stage, confirmed_hypotheses, is_multistage,
    chain_description}
   ↓
프론트:
   · IncidentTypeCompass 점 이동 (posteriorToXY)
   · ConfidenceGauge / HypothesisScoreBar 갱신
   · NextCluePanel candidates 재렌더
   · zone === 2 → AttackChainCard 등장
   · confidence_reached → notify 카드
```

### 3.6 컴퍼스 시각화 — IncidentTypeCompass

> 학술 근거: Pearl 1988 Belief Simplex Projection — barycentric 가중평균

```
8 사고유형 anchor — 단위원 위 45° 간격 (12시 시작, Kill Chain 시계방향):
  PHISH(1) → CRED(2) → PRIV(3) → INSIDER/MISCFG(4) → AUDIT(5) → DATA(6) → RANSOM(7)

점 위치 = Σ posterior[h] × anchor[h] (무게중심)
   ↓ Phase P.18 재설계 (2026-05-27, KBW)
   · 좌표 = posterior + stageDepth 만 (결정론적)
   · zone/regress 의존 제거 (전역 상태 의존 차단)
   · stage 전환 시 stageDepth 1 부터 → 자연 중앙 재시작
   · stage 별 독립 polyline (다른 색)
```

| 시각 요소 | 의미 |
|---|---|
| 내부 원 (R×0.5) amber | Zone 1 경계 (광범위 탐색) |
| 외부 원 (R) emerald (zone=2) | Zone 2 경계 (사고유형 chain 구체화) |
| 점 (mint) | 현재 사후확률 무게중심 |
| polyline (stage 별 색) | 단서 채택 궤적 |
| anchor glow | confidence_reached primary 강조 |
| ⤺ 회귀 권고 배지 | entropy ≥ 2.0 OR top1-top2 gap < 0.10 |

| 다단계 chain | **MITRE ATT&CK Flow 2023** + **Mandiant M-Trends 2024** | `stage_transition.compute_stage_prior` |
| 정찰 단서 우선 | **NIST SP 800-86 §4.1** Initial Triage | `ReconClueCard`, `recon-options` |
