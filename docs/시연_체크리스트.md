## 0. 사전 준비 (5분)

### 백엔드

```bash
cd cloud/backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt # Linux/Mac: .venv/bin/python
.venv/Scripts/python.exe -m db.init_db # DB 초기화 + 시드 적재
.venv/Scripts/python.exe -m core.sherpa.embed_kb --reset # ★ KB 15청크 → ChromaDB 적재 (첫 실행 시 ONNX 모델 ~80MB 다운로드, 30~40초)
.venv/Scripts/python.exe -m uvicorn main:app --reload --port 8000
```

> ⚠️ `embed_kb --reset` 빠뜨리면 RAG 가 키워드 fallback 으로 동작 (V-8 우측 패널이 `engine: keyword`). 시연 영상에서 의미 검색 임팩트가 줄어듦. 모델 캐시 위치는 `~/.cache/chroma/onnx_models/all-MiniLM-L6-v2/` — 한 번 받으면 오프라인 OK.

성공 시 `http://localhost:8000/docs` 에서 Swagger UI 열림. **확인 포인트**:
- `GET /api/health` → `{"status":"ok", ...}` 응답
- Swagger UI 좌측에 `intake / ingestion / analysis / sherpa / board / report / common` 7개 그룹 모두 표시
- `GET /api/sherpa/kb` → `data.rag` 필드에 `engine: "chromadb", indexed: 15` 확인 (키워드 fallback 아닌지 검증)

### 프론트엔드

```bash
cd cloud/frontend

```
