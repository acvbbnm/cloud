# 추가 기능 백로그 (확정 보류)

> **운영 정책**: 본 문서의 항목은 **설계서 SF/SNF/UF 21개가 모두 완료된 후** 검토한다.
> 학기 마감 시점에 시간 여유가 있고, 시연/평가 가치가 명확할 때만 채택.
>
> 마지막 갱신: 2026-05-14

---

## 0. 박제 이유

walking-skeleton 8/8 종결 + Layer 3 깡통 동작까지 끝낸 시점에 떠오른 아이디어들. **설계서에 없는 기능**이라 무리하게 추가하면 (a) 설계서 명세 미완료로 감점 (b) 머지 충돌 위험 (c) 시연 안정성 저하. 따라서 **설계서 100% 완료 후 재검토** 정책으로 보류.

## 1. 🌐 그래프 분석 (NetworkX in-memory, Neo4j 도입 보류)

**도입 판단**: Neo4j 풀 도입은 시간 대비 ROI 낮음. NetworkX in-memory 채택 권장. 별도 인프라 0, 학술 가치 ⭐⭐⭐⭐.

| ID | 기능 | 동작 | 가치 |
|---|---|---|---|
| **G1** | 공격 경로 탐색 | `attack_events ⋈ ocsf_events` 를 DiGraph 로 빌드 → `shortest_path(actor, resource)` | 침해 추적 단순화 |
| **G2** | 요충 노드 식별 | `betweenness_centrality` → "가장 많이 거쳐가는 IP/계정" 강조 | 우선 차단 대상 추천 |
| **G3** | 관련 사건 클러스터 | `weakly_connected_components` → 같은 actor가 일으킨 의심 활동 그룹화 | 사고 범위 자동 묶음 |

**구현 위치**: `core/analysis/graph_builder.py` (신규) + `GET /api/analysis/graph?caseId=` 엔드포인트 + V-5 "🧠 그래프 분석" 패널.
**의존성**: `networkx` 1 패키지 (별도 인프라 X).
**추정**: 1~2일.

## 2. 🔍 AI 가시화 (시연·평가 도구)

**핵심 명제**: "AI는 판단하지 않지만 무엇을 하는지 보여줘야 평가에서 손해 안 봄."

### 시각적 단서 (코드)

| ID | 기능 | 어디 | 효과 | 추정 |
|---|---|---|---|---|
| **U1** | **AI/규칙 배지** ⭐ 가장 중요 | 모든 화면 응답 카드 | "📋 규칙 기반" (V-1·V-3·V-4·V-6) vs "🤖 AI 검색·요약" (V-5·V-8) 명시 | 🟢 반나절 |
| **U2** | AI 처리 단계 라이브 | V-8 응답 직전 | `1) KB 검색 → 2) 청크 점수화 → 3) 응답 생성 → 4) 출처 첨부` 단계별 페이드인 | 🟢 반나절 |
| **U3** | 출처 청크 펼침 | V-8 sources 칩 클릭 | 칩 클릭 → KB 청크 원문 1~2문장 표시. "이 답은 저기서 나왔다" 검증 | 🟢 반나절 |
| **U4** | KB 검색 통계 패널 | V-8 우측 | "이 세션 검색 7회 / hit 평균 3.2건 / 인용 11건 (ATTACK 5·CASE_DB 4·PLAYBOOK 2)" | 🟢 반나절 |
| **U5** | 신뢰도 게이지 | V-5 brief | 텍스트 "신뢰도 medium" → 게이지 막대 + "왜 medium인가" 펼침 | 🟢 반나절 |
| **U6** | **AI 트레이스 콘솔** ⭐ 발표 무기 | 새 라우트 `/dev/ai-trace` | 라이브 로그 — sherpa 호출이 일어날 때마다 단계 로그 누적 (`/chat` 토큰 → KB hit → generate) | 🟡 1일 |

### 발표·영상 단서 (자료 제작)

| ID | 단서 | 효과 |
|---|---|---|
| **P1** | Before/After 표 | "수동 분석 90분 → 시스템 12분 + 빠진 증거 자동 발견" |
| **P2** | AI 응답 → KB 청크 → 원본 문서 4단계 추적 도식 | "AI 환각 없음, 모든 응답 검증 가능" 시각화 |
| **P3** | "AI에게 판단을 안 맡긴 이유" 슬라이드 | 증거 무결성 + 환각 위험 + 법적 효력 — 보수적 설계를 강점으로 |
| **P4** | 정량 메트릭 | 노이즈 압축률·유사 사례 재현율·갭 정확도·평균 응답 시간 |
| **P5** | 데모 영상 출처 칩 클로즈업 | "보세요, 이 답의 근거" |
| **P6** | 깡통 vs 실 모델 비교 시연 | Ollama 통합 후 같은 쿼리로 나란히 비교 |

## 3. 🪶 로그 노이즈 필터링

**필요성**: 사용자 의문 "AI가 로그를 줄여주는 것도 아니다" 대응. 설계서엔 없는 요구사항이지만 시스템 가치 부각.

| ID | 기능 | 어디 | 효과 | 추정 |
|---|---|---|---|---|
| **A1** | 연속 활동 압축 | V-3 OCSF 토글 | 같은 `actor+activity_name` 60초 내 N회 반복 → 1건 + count 배지. 클릭 시 펼침 | 🟢 소 |
| **A2** | 매핑된 것만 보기 | V-3 상단 체크박스 | `[ATT&CK 매핑된 이벤트만 표시]` 토글 | 🟢 소 |
| **A3** | 위험도 임계값 슬라이더 | V-6 히트맵 위 | `risk_score ≥ 50` 슬라이더 동적 필터 | 🟢 소 |
| **A4** | actor/IP 클러스터링 | V-3 신규 카드 | 같은 actor 이벤트 묶음 카드. 클릭 → 그 actor 활동 타임라인 | 🟡 중 |

**학술 가치**: A1에 **압축률 메트릭 측정** 추가 시 논문화 가능 ("로그 노이즈 압축률 84%").

## 4. 🧭 AI 보조 인사이트 (수사관 워크플로 보강)

**필요성**: 사용자 의문 "AI가 가이드도 안 해주고 인사이트 보조도 부족" 대응.

| ID | 기능 | 어디 | 효과 | 추정 |
|---|---|---|---|---|
| **B1** | 시스템 구성 토폴로지 시각화 | V-1 Step3 or V-5 상단 | Step2 입력을 노드-엣지 도식으로 자동 생성. 침해된 노드는 빨간 테두리 | 🟡 중 |
| **B2** | 유사 사례 자동 인용 | V-5 보드 상단 띠 | 현재 case 의 기법 시퀀스 → `case_db.json` 에서 3개 유사 사례 칩. 클릭 → timeline 토글 | 🟢 소 (RAG 이미 있음) |
| **B3** | 공격 체인 자동 추정 | V-5 "AI 제안" 버튼 | 매핑된 기법들을 Kill Chain 순서로 정렬 + 노드 자동 생성 (수락/거부) | 🟡 중 |
| **B4** | 사고 한 문단 요약 | V-7 진입 시 / V-5 메모 카드 | "2026-05-14 02:34, NCP admin-user … (ATT&CK 5기법, risk 87)" | 🟢 소 |
| **B5** | 우선 조사 영역 추천 | V-3·V-4 상단 카드 | risk_score 합산으로 "이 actor/IP/서비스 우선" 3개 추천 | 🟢 소 |
| **B6** | 타임라인 자동 시각화 | V-5 하단 패널 | 보드 노드들 시각 순 가로 타임라인. 호버 시 raw 미리보기 | 🟡 중 |

**비고**: B2 는 SF-05/06/09 가 실 RAG 로 가면 자연스럽게 일부 흡수됨.

## 5. 추천 패키지 (시간 여유 시 채택)

### 🎁 Compact (3~4일) — 최소 임팩트
- U1 (AI/규칙 배지) + U3 (출처 펼침) + B2 (유사 사례 인용)
- 시연 안정성 +1, 발표 명제 명확

### 🎁 Balanced (5~7일) — 권장
- Compact + G1·G2 (NetworkX 그래프 분석) + A1·A4 (노이즈 필터링)
- 학술 + 시연 가치 균형

### 🎁 Showcase (8~10일) — 시간 충분 시
- Balanced + U6 (AI 트레이스 콘솔) + B1 (시스템 구성 시각화) + B3 (공격 체인 자동 추정)
- 발표 무기 풀세트
