## 4. 발견된 갭·이슈

### P0 — 즉시 처리 → ✅ **2차 수정으로 모두 해소**
1. ~~**`GET /api/actions` 라우터 미구현**~~ → **해소** (`api/common.py` 신설, 22/22 API 100%)
   - 검증 흐름: 케이스 생성 → 노드 생성(default CONFIRMED) → PATCH REJECTED → `/api/actions` 1건 `REJECT on chain_node (detail: {from:CONFIRMED, to:REJECTED})` 정확 반환

### P1 — 회의 후 처리
2. **`/api/report/export?format=pdf`** — 본 테스트는 docx만 검증. PDF 변환은 별도 (이전 갭 분석 보고서의 C3 항목과 동일)
3. ~~**`POST /api/analysis/normalize` 응답 rate 0%**~~ — **정상 동작**: 이전 케이스 OCSF 데이터 누적 모드. 새 raw 1건이 이미 처리됐다면 추가 정규화 대상 0건 = 정상.

### P2 — 향후
4. **L3 chat 응답 시간 100초+** — 스트리밍 응답 적용 권장 (`stream=true`)
5. ~~**/api/sherpa/brief response.technique_id=None**~~ — **테스트 페이로드 오류**: brief는 `eventId(attack_id)` 받는데 테스트가 `technique_id`로 보냈음. API는 정상.

### 부수 발견 (정책 확인)
- **새 ChainNode 기본 status = CONFIRMED** (`db/models.py:158` + `core/board/chain.py:32`).
  → 새 노드를 다시 CONFIRMED로 PATCH하면 상태 변경 없음 → action_logs INSERT 안 함 (의도된 동작). ACCEPT 액션은 사실상 발생할 일이 없고, REJECTED → CONFIRMED 흐름이거나 명시적 PENDING 시드가 있어야 발생. CLAUDE.md `NodeStatus = CONFIRMED | REJECTED` 정책과 일치.
