# 시연 시나리오 — NCP 복합사고 (CREDENTIAL_THEFT → PRIVILEGE_ESCALATION → DATA_EXFILTRATION)

> **CSP**: Naver Cloud (NCP) · **사고유형(복합)**: CREDENTIAL_THEFT + PRIVILEGE_ESCALATION + DATA_EXFILTRATION · **심각도**: critical
> **공격자 외부 IP**: 45.140.17.22 (A·진입), 115.91.214.5 (B·C 운영) · **피해 계정**: svc-deploy → 백도어 attack-sim
> **설계 목표**: ① 복합 사고유형 ② A→B→C 체인 재구성 ③ B→C→A 역추적("꼬리에 꼬리") ④ 쓰레기 로그 혼입 후 분류 입증

## 0. 이 시나리오가 기존 단일 시나리오와 다른 점

| 항목 | 기존(01~03) | 본 복합 시나리오 |
|------|------------|------------------|
| 사고유형 | 단일 1종 | **3종이 한 세션에 얽힘** |
| 로그 구성 | 공격 로그만(깔끔) | **공격 로그 + 무관 쓰레기 로그(노이즈) 혼입** |
| 추적 | 일방향 타임라인 | **A→B→C 정방향 + B→C→A 역방향 피벗** |
| 검증 포인트 | 매핑률 | **매핑(공격)/미매핑(노이즈) 분리 + 피벗 재구성** |

샘플 로그(`01_사고유형선정_ncp_composite.json`)에는 **공격 21건 + 쓰레기(`_noise`) 6건 = 27건**이 시간순으로 섞여 있다. 분류기가 쓰레기를 `unmapped_raw` 로 떨궈내고 공격만 ATT&CK 기법으로 매핑하는지가 1차 검증이다.

## 1. 사고 개요 (수사관 관점)

야간 배치 모니터링에서 **운영 Object Storage(고객 DB·결제) 대량 내보내기**가 탐지됐다. 처음엔 단순 유출로 보였으나, 내보내기를 수행한 계정 `attack-sim` 이 **사고 당일 새로 생성된 서브계정**이었다. 수사관은 "누가 이 계정을 만들었나"를 거슬러 올라가며 자격증명 탈취 → 권한 상승 → 유출의 **3단 복합 사고**임을 확인한다.

## 2. 1단계 — 사고유형 선정용 로그 업로드 (쓰레기 포함)

- **파일**: `01_사고유형선정_ncp_composite.json` (공격 21 + 쓰레기 6 = 27건)
- **쓰레기 로그 6건** (모두 미매핑되어야 정상):
  `Get Server Instance List` · `Get Monitoring Data` · `Get Billing Detail` · `Get NAS Volume List` · `Update Server Memo` · `Get Auto Scaling Activity Log`
- **시스템 판정**: 매핑된 공격 기법 조합이 세 묶음으로 군집 →
  - **A 묶음** T1078.004(로그인 실패·성공 공통)·T1552·T1098.001 → **CREDENTIAL_THEFT**
    - ※ 도구 매핑 주의: 로그인 실패(`actionResultType:FAIL`)는 **분석가 해석상 T1110(Brute Force)** 이나, 현재 MVP AttackMapper 는 룰 `condition` 을 평가하지 않아(`activity_name` 만 매칭) **실패·성공 로그인 모두 T1078.004 로 표기**된다. T1110/T1566(피싱) 룰은 조건부라 미발화. 8절 검증 참조.
  - **B 묶음** T1087.004·T1136.003·T1098·T1098.001 → **PRIVILEGE_ESCALATION**
  - **C 묶음** T1619·T1537·T1530·T1531 → **DATA_EXFILTRATION**
- 수사관은 **복합(CREDENTIAL_THEFT 주(主) + PRIVILEGE_ESCALATION·DATA_EXFILTRATION 종(從))** 으로 확정.

## 6. 역추적 — B→C→A "꼬리에 꼬리를 무는" 재구성

정방향(A→B→C)뿐 아니라, **중간 단서에서 시작해 양쪽으로 뻗어가는** 추적이 성립한다. 시연 핵심.

```
                       ┌──────────── (B→A 역추적) ────────────┐
                       │  "attack-sim 을 누가 만들었나?"       │
                       │  Create sub account 의 주체           │
                       ▼  = svc-deploy / 45.140.17.22          │
        ┌──────────────────────┐                               │
   A ◀──┤ 45.140.17.22 (외부IP) ├── 이 IP 의 과거 이력 조회 ───▶ 14:00 Login FAIL ×3 (A 발견)
        └──────────────────────┘
                       ▲
                       │  (B 시작점) Create sub account attack-sim  ★
                       │
                       ▼  (B→C 정추적) "attack-sim 은 뭘 했나?"
        ┌──────────────────────┐
   C ◀──┤ attack-sim (계정)     ├── 이 계정의 행위 추적 ───────▶ 14:27 Export / 14:40 GetObject (C 발견)
        └──────────────────────┘
                       │
                       ▼  (C→A 루프 폐합) GetObject 의 IP = 45.140.17.22
                          → A 의 무차별 대입 IP 와 동일 → 단일 행위자 확정 ◎
```

- **피벗 키 1 — 계정 `attack-sim`**: B(생성)와 C(유출)를 잇는다. 생성 이벤트의 `productData.targetAccount` ↔ 이후 동일 계정 행위.
- **피벗 키 2 — IP `45.140.17.22`**: A(대입)와 C(최종 GetObject)를 잇는다. 공격자가 마지막에 첫 IP를 재사용 → **C에서 A로 직접 점프**.
- **피벗 키 3 — 계정 `svc-deploy`**: A(탈취 피해 계정)와 B(백도어 생성 주체)를 잇는다.
- 세 피벗이 삼각형으로 닫혀 **A·B·C 어느 노드에서 출발해도 나머지 둘을 복원** → 재구성·꼬리물기 추적 동시 입증.

## 7. 수사 결론

- **확정 사고유형**: 복합 — CREDENTIAL_THEFT(진입) → PRIVILEGE_ESCALATION(백도어·권한) → DATA_EXFILTRATION(유출), 단일 행위자.
- **노이즈 처리**: 쓰레기 6종(샘플) + 1종(수집물)은 전부 `unmapped_raw` 로 분리 → 공격 신호만 체인에 진입. **분류 입증 완료.**
- **갭(GapDetector)**: 없음 — 세 피벗 키(attack-sim, 45.140.17.22, svc-deploy)로 인과 연결 완결.
- **후속 권고**: 45.140.17.22·115.91.214.5 차단, svc-deploy 자격증명 회수·MFA 강제, 백도어 attack-sim 즉시 삭제, prod-customer-db / prod-payments 유출 통지, 서브계정 생성 권한 최소화.
