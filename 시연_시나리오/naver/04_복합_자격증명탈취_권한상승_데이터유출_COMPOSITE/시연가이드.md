## 1. 시연 골격 — "3개를 보여주면 끝"

**먼저 🧭 인지(cognition)로 출발**한 뒤, 이 데모가 증명하는 3깃발을 꽂는다.

- **🧭 인지(2막)** — 로그를 보기 전, 운영팀 알람(약한 신호)만으로 **복합 사고임을 *인지*** (1차 정찰). 이게 모든 후속 행동의 출발점.
1. **🗑 분류(노이즈 필터링)** — 쓰레기 로그가 `unmapped`로 떨어지고 공격만 ATT&CK 기법으로 매핑.
2. **🔗 재구성(A→B→C)** — 탈취→권한상승→유출이 시간순 체인으로 이어짐.
3. **🐍 꼬리물기(B→C→A)** — 백도어 계정·재사용 IP라는 **피벗 키**로 어느 지점에서 시작해도 단일 행위자로 수렴.

> 인지 경로 = **약한 신호(2막) → 가설/추천 단서 → 로그 소환·채택(3막) → 확정**. 로그부터 던지지 말고 "어떻게 알게 됐는지"부터 보여주는 게 핵심.

### 🎬 2막 — **1차 정찰 / 사고 인지** (V1 Step3 증거 트리 · `/setup`) ★데모 출발점

> **이 막이 핵심 인지 경로다.** 로그를 아직 안 봤다. 운영팀의 알람·정황만으로 "이게 무슨 사고일 가능성이 큰가"를 **약한 신호(Q2A 정찰 단서)** 로 가늠하는 단계. NIST SP 800-86 §4.1 Initial Triage.

- **화면**: Step3 진입 시 cold-start 상태. 상단에 두 안내가 뜸:
  - **기본 수사 가이드(EntryGuideBanner)** — 사고유형 무관 필수 로그 점검표(사후확률 영향 X, 단순 안내).
  - **1차 정찰 카드(ReconClueCard)** — 노란 박스 제목 **"1차 정찰 (사고 인지 단계)"**, 질문 **"어떤 이상이 있었나요?"** + 약한 신호 옵션들.
- **클릭(정찰 단서 채택 — 시나리오 정황에 맞춰 3개)**:
  1. **`Object Storage 대량 활동`** → DATA_EXFILTRATION·RANSOMWARE·MISCONFIG·INSIDER 신뢰도 ↑ (야간 배치가 잡은 그 신호)
  2. **`비국내 IP 접근`** → CREDENTIAL_THEFT·PHISH·RANSOMWARE ↑ (45.140.17.22)
  3. **`권한 변경 알람`** → PRIVILEGE_ESCALATION·INSIDER ↑ (attack-sim에 Administrator 부여)
- **멘트**: "아직 로그를 한 줄도 안 봤습니다. **운영팀 알람만으로** — 오브젝트 스토리지가 비정상적으로 바빴고, 비국내 IP가 붙었고, 권한이 바뀌었다 — 이 세 약한 신호를 넣자 신뢰도 게이지가 **유출·자격증명탈취·권한상승 쪽으로 동시에** 기웁니다. **복합 사고임을 여기서 *인지*** 하는 거죠."
- **화면 결과**: 우측 **현재 신뢰도 게이지**가 균등(8종 분산)에서 **상위 후보 3종(DATA_EXFILTRATION/CREDENTIAL_THEFT/PRIVILEGE_ESCALATION)** 으로 비균등하게 솟음. 단일 단서로 한 종 99% 쏠림이 아니라 **복합을 가리키는 분포**가 핵심.
- **주의**: "어떻게 알게 됐나요?"(발견 경로)는 **메타 정보라 사후확률 영향 없음**(V1.fix). 변별력 있는 건 "어떤 이상이 있었나요?"(Q2A) 옵션뿐.

### 🎬 3막 — 추천 단서 → 로그 소환 & 채택 (V1 Step3 · `/setup`)

> 인지(2막)가 끝나면 **"다음 단서 후보"** 가 사고유형에 맞춰 갱신된다. 수사관은 그걸 보고 **"아, 그 로그 있었던 것 같은데? 가져와서 봐야겠다"** 하고 실제 로그를 소환·분석한다. (인지 → 가설 → 증거 소환의 자연 흐름)

- **목표**: `01_사고유형선정_ncp_composite.json`을 적재해 **노이즈가 섞인 상태에서 공격 신호만 부각**되는 장면.
- **클릭**:
  1. 우측 **가설/다음 단서 후보** 에서 추천 단서(예: 대량 내보내기·권한부여) 확인 → "이 로그가 있을 것" 가설.
  2. 좌측 **[로그]** 토글 → `01_사고유형선정_ncp_composite.json` 업로드.
  3. **분석 로그 적재함**에 이벤트가 쌓임. 공격 이벤트엔 **기법 채택 칩**(예: `➜ T1537 Complete For Exporting… · attack-sim · 115.91.214.5`), **노이즈 6건엔 채택 칩 없음**(추출 가능한 기법 없음).
  4. 대표 공격 칩 2~3개 클릭 → 단서 채택 → 게이지가 2막의 약한 분포에서 **확신(상위 후보 굳어짐)** 으로 전환.
- **세렌디피티(어? 이런 로그도) 포인트**: 적재함을 훑다 추천에 없던 이벤트(예: `Decrypt root password`)를 보고 **"어? 이것도 있네"** 하며 그 칩도 채택 → 가설에 없던 단서도 흡수됨을 시연.
- **멘트**: "인지한 사고유형이 '이런 로그가 있을 것'이라 가리켜서 가져왔습니다. 보시면 `Get Billing Detail`·`Get Monitoring Data` 같은 **평범한 조회 로그는 채택 버튼 자체가 없습니다** — 도구가 ATT&CK 룰에 안 걸리는 걸 이미 솎아낸 거죠."
- **화면 결과**: 27건 중 **공격 21건만 기법 보유, 노이즈 6건 미매핑** → 🚩깃발1(분류) 첫 시각화.
- **검증 수치(슬라이드 가능)**: 01 파일 = 공격 21 / 노이즈 6 / 오매핑 0 / 누락 0.

| 로그도 안 봤는데 사고유형을 어떻게 인지하나? | 2막 1차 정찰(NIST SP 800-86 §4.1 Initial Triage). 운영팀 알람=약한 신호(Q2A 단서)를 채택하면 베이지안 사후확률 게이지가 비균등하게 기운다. 단정이 아니라 *가설 수립* — 이후 로그·체인으로 확정. |
| 정찰 단서 3개로 왜 1종이 아니라 3종이 뜨나? | 복합 사고라 약한 신호가 여러 유형을 동시에 가리키는 게 정상. 한 단서로 한 종 99% 쏠림이면 오히려 단일 사고. 분포가 복합을 가리키는 게 핵심. |
| "어떻게 알게 됐나요?"(발견 경로)는 왜 게이지에 영향이 없나? | 그건 메타 정보(IG=0)라 사후확률 미반영. 변별력 있는 건 "어떤 이상이 있었나"(Q2A)뿐. (V1.fix) |
| 노이즈가 진짜 자동으로 걸러진 거냐? | 네. `attack_rules/rules.json` 정규식에 안 걸리면 `unmapped`. 조작 없이 6+1건 전부 미매핑. (시나리오.md 8절 검증표) |
| 로그인 실패가 왜 T1110이 아니냐? | MVP 매퍼가 룰 조건(FAIL)을 미평가. 실패·성공 모두 T1078.004. Brute Force는 보드 수동 확정. |
| 단일 행위자라는 근거는? | 피벗 3개: 계정 `attack-sim`(B↔C), IP `45.140.17.22`(A↔C 재사용), 피해계정 `svc-deploy`(A↔B). |
| 복합인데 케이스 유형이 1개인 이유? | 케이스는 최종 임팩트(DATA_EXFILTRATION)로 접수, 선행 2단계는 체인 재구성에서 드러남(MVP 정책). |
| `.locked`/암호화는? | 이건 NHN 랜섬 시나리오. NCP는 유출(Export/GetObject)이 임팩트. |
