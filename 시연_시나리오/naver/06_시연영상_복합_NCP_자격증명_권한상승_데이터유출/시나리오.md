## 1. 사고 개요 (수사관 관점 — 1차 인지)

야간 모니터링에서 **운영 Object Storage(고객 PII·결제 원장) 대량 내보내기**가 포착됐다. 내보내기를 수행한 계정 `svc-backup` 은 **사고 당일 새로 생성된 서브계정**이었고, 그 생성 주체는 평소 내부망에서만 동작하던 배포용 계정 `deploy-agent` 였다. 수사관은 "누가 이 계정을 만들었나 → 그 계정은 어떻게 탈취됐나"를 거슬러 올라가며 **자격증명 탈취 → 권한 상승 → 데이터 유출** 의 3단 복합 사고임을 확인한다.

**1차 정찰(인지 단계)에서 선택되는 우리 시스템상의 이상징후 2종**:
1. **외부 IP에서의 반복 로그인 실패 직후 성공** (평소 내부망 전용 계정이 외부 IP로 인증) → 자격증명 탈취 신호
2. **신규 서브계정 생성 직후 관리자 정책 부여 + 대량 스토리지 내보내기** → 권한 상승·유출 신호

## 3. 역추적 — B→C→A "꼬리에 꼬리를 무는" 재구성 (시연 핵심)

정방향(A→B→C)뿐 아니라, **중간 단서(B)에서 출발해 양쪽으로 뻗는** 추적이 성립한다.

```
                  (B 시작점) Create sub account → svc-backup  ★
                  ────────────────┬───────────────────────────
                                  │
        ┌─────────── B→A 역추적 ───┴─── B→C 정추적 ───────────┐
        │ "svc-backup 을 누가 만들었나?"   "svc-backup 은 뭘 했나?"
        ▼ 생성 주체 = deploy-agent/203.0.113.77   ▼ 계정 행위 추적
   A 발견: 13:20 deploy-agent Login FAIL ×3    C 발견: 14:02 Export / 14:15 GetObject
        │                                        │
        │  203.0.113.77 (A 진입 IP)              │  GetObject 의 sourceIp = 203.0.113.77
        └──────────────── C→A 루프 폐합 ─────────┘
                   동일 IP → 단일 행위자 확정 ◎
```

**세 피벗 키 (삼각형 폐합)**
- **피벗 1 — 계정 `svc-backup`**: B(`Create sub account` 의 `targetAccount`)와 C(유출 수행 주체)를 잇는다.
- **피벗 2 — IP `203.0.113.77`**: A(무차별 대입)와 C(최종 `GetObject` 의 `sourceIp`)를 잇는다. 공격자가 마지막에 첫 IP를 재사용 → **C에서 A로 직접 점프**.
- **피벗 3 — 계정 `deploy-agent`**: A(탈취 피해 계정)와 B(`Create sub account` 의 생성 주체)를 잇는다.
- 세 피벗이 삼각형으로 닫혀 **A·B·C 어느 노드에서 출발해도 나머지 둘을 복원** → 정방향 재구성·역방향 꼬리물기 동시 입증.

> 이 세 피벗은 **수집 파일(02A/02B/02C)에도 그대로 보존**되어 있어, 가이드 수집물만으로 보드에서 동일한 삼각형을 재현할 수 있다.
> - 02A: `deploy-agent` + `203.0.113.77` (A)
> - 02B: `Create sub account → svc-backup`, 생성자 `deploy-agent/203.0.113.77` (피벗 1·3)
> - 02C: `GetObject sourceIp=203.0.113.77`, 주체 `svc-backup` (피벗 1·2)

## 4. 수집 3경로 (수사관 직접 수행)

| 단계 | 파일 | 수집 방식 | 실제 콘솔 경로(hint) | 핵심 단서 |
|------|------|----------|---------------------|-----------|
| A | `02A_…자격증명탈취_적재.json` | **사전 제작 로그 적재**(드래그&드롭) | NCP Console → Monitoring → Activity Tracer → `Login` 필터 (CT-NCP-IAM-001) | deploy-agent FAIL×2→SUCCESS, 203.0.113.77 |
| B | `02B_…권한상승_라이브콘솔.json` | **실제 콘솔에서 라이브 내보내기** | NCP Console → Monitoring → Activity Tracer → `Create sub account / AttachPolicy` 이벤트 → Object Storage 내보내기 (CT-NCP-PRIV-002) | svc-backup 생성·관리자 정책, **List Sub Account Policy(01에 없음)** |
| C | `02C_…데이터유출_AI검색.json` | **로그 적재 + AI 검색 질의** | NCP Console → Object Storage 접근 로그 + Activity Tracer `Export` 필터 (CT-NCP-DE-001/002) | GetObject 203.0.113.77 재사용 |

- **B(라이브)** 가 가장 쉬운 단일 카테고리(IAM 권한변경 이력) → Activity Tracer에서 `Create sub account`·`Attach policy` 필터 후 Object Storage로 JSON 내보내기 → 그 파일을 그대로 업로드. **수집 가이드 + 실제 선택 동작을 영상에 담는 대상.**
- **A** 는 미리 만든 `02A` 를 적재만.
- **C** 는 `02C` 적재 후 AI 셰르파(`/sherpa`)에 *"prod-customer-pii 를 외부 IP에서 가져간 행위가 있나? 그 IP가 초기 침투 IP와 같은가?"* 질의 → `203.0.113.77` 재사용을 시스템이 부각.
