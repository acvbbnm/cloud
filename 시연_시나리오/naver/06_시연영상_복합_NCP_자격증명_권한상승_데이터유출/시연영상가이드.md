### 3-D. 방향별 단서 채택 순서 ★촬영 기준표

> **원칙**: 적재함(로그 풀)은 **고정**이다 — JSON을 방향마다 새로 만들지 않는다. 바뀌는 것은 **Evidence Tree에 단서를 채택(`expandTree`)하는 클릭 순서**뿐. 매 채택마다 `path`에 노드가 쌓이고 베이지안 사후확률이 갱신된다. 아래 순서대로 **적재함 row → [채택]** 또는 **컴퍼스/IG 후보 클릭**을 누르면 같은 풀에서 6가지 궤적이 모두 재현된다.
> **베이지안 성질**: 최종 확률은 채택 순서와 무관(곱). 달라지는 건 **컴퍼스 trail 궤적·confidence 게이지 상승 경로** — 역추적 시연의 시각적 차별점이 여기서 나온다.

| 방향 | 채택 순서 (피벗 경로) | 1→2 hop 근거 | 2→3 hop 근거 |
|------|----------------------|--------------|--------------|
| **A→B→C (정방향)** | deploy-agent 무차별대입(A) → Create sub account/svc-backup(B) → Export·GetObject(C) | 피벗③ 계정 deploy-agent (A의 행위자 = B의 생성 주체) | 피벗① 계정 svc-backup (B가 만든 계정 = C의 유출 주체) |
| **B→C→A** ★ | Create sub account/svc-backup(B) → svc-backup Export·GetObject(C) → GetObject IP 203.0.113.77(A) | 피벗① 계정 svc-backup | 피벗② IP 203.0.113.77 (C의 GetObject IP = A의 진입 IP) |
| **B→A→C** | Create sub account/svc-backup(B) → 생성자 deploy-agent/203.0.113.77(A) → IP 203.0.113.77 재사용 GetObject(C) | 피벗③ 계정 deploy-agent | 피벗② IP 203.0.113.77 |
| **C→B→A** | GetObject·Export(C) → svc-backup 생성 이벤트(B) → 생성자 deploy-agent(A) | 피벗① 계정 svc-backup | 피벗③ 계정 deploy-agent |

- **촬영 동선**: 정방향(A→B→C) 1회 + 역추적(B→C→A) 1회면 핵심 입증 충분. 시간 여유 시 B→A→C 한 번 더 보여 "어느 hop을 먼저 타도 닫힌다"를 강조.
- **각 방향 전환 시**: `⟲ 초기화`(우상단) → 시작 노드 단서부터 다시 채택. `다음 단계 추적(multi-stage)` 버튼으로 확정 가설을 anchor 삼아 다음 hop으로 진행.
- **노드 단서 = 적재함의 어떤 로그인가**: A=`deploy-agent Login`(T1078.004) / B=`Create sub account`(T1136.003) / C=`GetObject`(T1530)·`Export`(T1537). 이 세 로그가 각 방향의 출발·경유점이다.

### 3-E. 다단계(multi-stage) 레이더 누적 — 단계별 로그 투입 순서 ★사고유형 3종 = 컴퍼스 선 3개

> **동작 확인(코드 근거)**: 컴퍼스(`IncidentTypeCompass`)는 trail을 **stage별로 분할해 독립 polyline**으로 그린다(`trailSegments`). `다음 단계 추적(multi-stage)` 버튼이 `advanceStage`를 호출하면 백엔드(`clue_tree_service.advance_stage`)가 ① 확정 가설을 `confirmed_hypotheses`에 **누적**하고 ② `STAGE_TRANSITION_MATRIX`(1-step 마르코프)로 다음 단계 사전확률을 **재기준화**하며 ③ `tree.stage += 1`. 이후 채택하는 단서는 새 stage로 적재되어 **중앙에서 다시 시작하는 새 색 선**으로 그려진다. → **3번 확정 = stage 1·2·3 = 컴퍼스에 색이 다른 선 3개**(녹색→파랑→보라). 사용자가 본 "레이더에 선 3개" 가 바로 이 누적 궤적이다.

| stage | 색 | 수렴 사고유형(확정) | **이 단계에서 채택할 적재함 로그(순서대로)** | 핵심 기법 | 다음으로 |
|-------|----|--------------------|----------------------------------------------|-----------|----------|
| **Stage 1** | 🟢 녹색 | `CREDENTIAL_THEFT` | ① `Login`(외부 IP 성공) → ② `Decrypt root password` → ③ `Change password` | T1078.004 · T1552 · T1098.001 | 확정 카드 → **`다음 단계 추적`** |
| **Stage 2** | 🔵 파랑 | `PRIVILEGE_ESCALATION` | ④ `Get Sub Account Policy List` → ⑤ `Create sub account`(svc-backup) → ⑥ `Attach policy to sub account`(AdministratorAccess) | T1087.004 · T1136.003 · T1098 | 확정 카드 → **`다음 단계 추적`** |
| **Stage 3** | 🟣 보라 | `DATA_EXFILTRATION` | ⑦ `List Buckets` → ⑧ `Request/Complete For Exporting`(prod-customer-pii) → ⑨ `GetObject` | T1619 · T1537 · T1530 | 확정 → `chain_description` 완성 |

- **마르코프 보강 효과**: `STAGE_TRANSITION_MATRIX`에서 CRED→PRIV, PRIV→DATA 가 최고 prior 경로다. 그래서 Stage 1 확정 후 Stage 2 단서가 더 빨리 confidence에 도달하고(전 단계 anchor가 다음 단계 사전확률을 끌어줌), 컴퍼스 선이 시계방향으로 자연스럽게 P2→P3→P6 anchor를 향해 뻗는다. **확정 가설은 0으로 동결**되어 다시 그 방향으로 안 튀고 다음 anchor로만 전진.
- **촬영 동선**: 적재함 row를 위 ①~⑨ 순서로 [채택]하되, ③·⑥·⑨ 직후 confidence 게이지가 차면 **확정 → `다음 단계 추적`**. 세 번 반복하면 `confirmed_hypotheses = [CREDENTIAL_THEFT, PRIVILEGE_ESCALATION, DATA_EXFILTRATION]`, `is_multistage=true`, 헤더에 `자격증명 탈취 → 권한 상승 → 데이터 유출` chain이 뜬다.
- **3-D 표와의 관계**: 3-D(방향별 채택 순서)는 **한 사고를 어느 hop부터 풀어도 닫힌다**는 *역추적* 시연용. 3-E(여기)는 **3종을 차례로 확정해 레이더에 선 3개를 쌓는** *정방향 다단계* 시연용. 영상에서는 3-E(정방향 누적)로 "사고유형 3개 선정"을 먼저 보여주고, 3-C/3-D(역추적)로 "삼각형 폐합"을 보여주면 흐름이 매끄럽다.
