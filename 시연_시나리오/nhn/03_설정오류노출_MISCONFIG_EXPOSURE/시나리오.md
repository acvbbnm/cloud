# 시연 시나리오 — NHN 설정오류 노출 (MISCONFIG_EXPOSURE)

> **CSP**: NHN Cloud · **사고유형**: MISCONFIG_EXPOSURE · **심각도**: high
> **내부 주체**: devops@victim.kr (172.30.10.6) · **외부 익명 접근**: 8.8.8.8, 185.220.101.7

---

## 1. 사고 개요 (수사관 관점)

외부 보안 제보로 "회사 Object Storage 컨테이너가 인터넷에 전체 공개되어 있고
설정 파일·DB 백업이 다운로드된다"는 신고가 들어왔다. 침입 흔적보다 **설정 실수**가
의심되어, 수사관은 CloudTrail 의 컨테이너·보안그룹·IAM 변경 이벤트를 확보해
**AI Sherpa** 에 업로드한다.

## 2. 1단계 — 사고유형 선정용 로그 업로드

- **파일**: `01_사고유형선정_nhn_misconfig_exposure.json`
- **내용**: devops 로그인 → **컨테이너 metadata `.r:*` 전체 공개** →
  **Security Group 0.0.0.0/0** → 서비스 계정 Admin 부여 → **외부 익명 다운로드**
- **시스템 판정**: 공개 권한 변경·과도 네트워크 개방·과도 권한 부여 조합이 ATT&CK
  **T1190(Exploit Public-Facing Application) / T1580(Cloud Infra Discovery) /
  T1078.001(Default/over-permissioned Accounts)** 로 매핑 → 사고유형 후보
  **MISCONFIG_EXPOSURE** 최상위 제시.
- 수사관은 **MISCONFIG_EXPOSURE 으로 확정**한다.

## 6. 수사 결론

- **확정 사고유형**: MISCONFIG_EXPOSURE (공개 설정 실수 → 외부 익명 데이터 유출)
- **수집 완료율**: REQUIRED 3종 + CORROBORATING 1종 확보 → 100%
- **갭(GapDetector)**: 없음 — 공개 설정 변경 시각과 외부 익명 다운로드가 인과로 연결.
  다만 설정 공개(09:05)와 외부 접근(11:30) 사이 추가 접근 여부는 컨테이너 액세스 로그로 보강 권고

  prod_db_dump.sql 1.8GB 유출 통지, 외부 IP(185.220.101.7) 접근 차단
